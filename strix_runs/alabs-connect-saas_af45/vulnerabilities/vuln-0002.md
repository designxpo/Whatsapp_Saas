# Hardcoded Secrets in Test Files

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-08-08 09:23:51 UTC
**Target:** /workspace/alabs-connect-saas
**CWE:** CWE-798
**CVSS:** 5.3
**Fix Effort:** Low

## Description

Several test files contain hardcoded secrets, such as 'test_app_secret', 'wanderly_signing_secret_2026', and 'skyline_signing_secret_2026'. While these are in test files, it is a security best practice to avoid hardcoding secrets even in non-production code.

## Evidence

Output from `rg "secret" /workspace/alabs-connect-saas/ -g "*test*"`:
```
/workspace/alabs-connect-saas/src/lib/__tests__/apiauth.test.ts:  const secret = "test_app_secret";
/workspace/alabs-connect-saas/src/lib/__tests__/scenario-travel.test.ts:    const SIGNING_SECRET = "wanderly_signing_secret_2026";   // stored plaintext = legacy path of readSecret
/workspace/alabs-connect-saas/src/lib/__tests__/scenario-realestate.test.ts:    const SIGNING_SECRET = "skyline_signing_secret_2026";   // stored plaintext = legacy path of readSecret
/workspace/alabs-connect-saas/src/lib/__tests__/embeddedsignup.test.ts:    process.env.META_APP_SECRET = "test-app-secret";
```

## Impact

Potential information disclosure and increased risk of accidental exposure of sensitive data if test files are ever exposed or mistakenly deployed to a production-like environment.

## Technical Analysis

The `rg` command revealed multiple instances of `secret` variables with hardcoded string values in various `*.test.ts` files. For example, `src/lib/__tests__/apiauth.test.ts` uses `const secret = "test_app_secret";`.

## Proof of Concept

1. Run `rg "secret" /workspace/alabs-connect-saas/ -g "*test*"` in the terminal.
2. Observe the output showing files with hardcoded secret strings.

```scdoc
rg "secret" /workspace/alabs-connect-saas/ -g "*test*"
```

## Remediation

1. Replace hardcoded secrets with references to environment variables or a dedicated secrets management system.
2. Ensure that test configurations clearly separate sensitive data from the codebase.
3. Implement a policy to disallow hardcoding of any secrets, even in test code.

## Assumptions

The hardcoded secrets are used only within test contexts and are not directly exposed in production environments. However, the presence of these secrets increases the risk of accidental exposure.
