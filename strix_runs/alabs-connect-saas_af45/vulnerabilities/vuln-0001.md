# Reflected XSS via Unsanitized URL in Live Chat Messages

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-08-08 09:23:09 UTC
**Target:** Live Chat Interface
**Endpoint:** /admin
**CWE:** CWE-79
**CVSS:** 6.3
**Fix Effort:** Medium

## Description

The `linkify` function in `LiveChatTab.tsx` improperly sanitizes user-supplied URLs before inserting them into `<a>` tags within chat messages. This allows attackers to inject arbitrary HTML attributes, leading to reflected Cross-Site Scripting (XSS).

## Evidence

Code analysis of `linkify` function in `LiveChatTab.tsx` shows direct interpolation of user-controlled `part` into the `href` attribute, enabling attribute injection. The `agent-browser` could not complete dynamic validation as the target application requires authentication and no credentials were provided.

## Impact

An attacker can execute arbitrary JavaScript in the victim's browser, leading to session hijacking, data theft, or defacement.

## Technical Analysis

The `linkify` function identifies URL-like strings using a regex. If a substring matches, it is directly inserted into the `href` attribute and the text content of an `<a>` tag. An attacker can close the `href` attribute with a double quote and inject event handlers (e.g., `onmouseover`) or other malicious attributes. While React typically provides some level of escaping, direct attribute insertion from unsanitized user input in this manner can bypass default protections, especially with carefully crafted payloads that leverage embedded quotes.

## Proof of Concept

1. An attacker sends a message containing a specially crafted URL-like payload.
2. The `LiveChatTab` component receives and renders this message.
3. The `linkify` function processes the payload, creating an `<a>` tag with injected attributes.
4. When a victim views the message and interacts with the malicious link (e.g., by hovering over it), the injected JavaScript code executes.

## Remediation

1. **Sanitize URL before use:** Before constructing an `<a>` tag, ensure that the URL `part` is properly HTML attribute encoded to prevent arbitrary attribute injection. Use a library like `dompurify` or a custom escaping function that specifically targets HTML attribute contexts.
2. **Validate URL scheme:** Implement strict validation to allow only safe URL schemes (e.g., `http`, `https`, `mailto`) and reject any others, such as `javascript:`, `data:`, or `vbscript:`. While React handles `javascript:` in `href` by default, combining it with attribute injection can still pose risks.
3. **Use React's built-in escaping for content:** For the text content of the `<a>` tag, ensure it is treated as plain text and not raw HTML, leveraging React's default escaping for JSX interpolated values.

## Assumptions

Assumes an attacker can control the message body sent to the chat interface, and that React's default attribute escaping mechanisms are bypassed by the crafted payload due to the direct string interpolation into `href` within the `linkify` function. Authentication to the `/admin` interface is required to view the vulnerable component.
